# Audit and stabilisation of 2026-11-06

> Generic record of the framework's audit of 6 November 2026: what was wrong, what changed and how it was validated.
> Project data is not here: a workspace keeps its own report. Subordinate to `methodology.md` §15.

## 1. Specification of the structural fixes (written before the changes)

| # | Area | Rule after the fix |
|---|---|---|
| S1 | Writes | Every whole-file write goes through `common.atomic_write`: an exclusive temporary file next to the target (a link planted at `<file>.tmp` is never followed), fsync, replace. Appended files are checked with `workspace_path` and opened without following a link. |
| S2 | Isolation | `history/` is refused whatever its case (`History/` on macOS and Windows is the same folder). |
| S3 | Lock | The lock file names its holder from the moment it exists (written aside, then linked into place). A lock that names nobody is abandoned after 10 s. Reentrancy is keyed by the real path. |
| S4 | Workbooks | One helper, `workbook_for(project, batch)`, decides the workbook of a batch from `excel.workbooks` (patterns) and `excel.file`; `QA_WORKBOOK` overrides it explicitly. The apply, `run_log.applied()`, the audit and the totals use it. Applying takes the workspace lock and saves to a temporary file that is verified before it replaces the workbook. |
| S5 | Results | A batch whose application cannot be read counts as not applied. A result without `ts` is flagged. Ties on the same instant are broken by an explicit `revision_of`, then the order of application, never by file modification time. Each current result says whether it is applied. Builds are grouped with `same_build`. |
| S6 | Run log | The run block's build and environment are fixed by the first result: a later `--build` cannot fill an empty build. Replacing a result needs `--replace` and prints what it replaces. Question is matched case-insensitively at the start. |
| S7 | Tickets | The analysis is validated completely before any write (types included). Sources are structured: `comment:<id>` (or a link to a comment) is a statement; `component:comments` is a fact of the collection. Content that could not be opened is recorded apart and stays not read. Children not expanded are listed as `not-expanded`. Tracker text inside the copyable prompt is marked as data. The context block says when a ticket changed after its analysis. |
| S8 | `/test-pbi` record | `check` reports what it could not compare and never says "nothing changed" without a comparison; `--reopen` returns the steps to review to pending. `published` needs a non-empty draft, key and confirmation reference, and refuses a key already used by another draft. A blocked step needs a note. Links from hosts not configured in `tickets:` are refused. |
| S9 | iOS | The iPhone backend (`device_ios.py`, `--platform ios`) is part of the main checkout; the preflight reports the iOS tools from `mobile.ios`, and `device.py check` gives the same ready/next report on both platforms. |
| S10 | Preflight | Configuration valid and ready to run are separate verdicts: each route ends with `Ready: yes` or `Ready: no — <capability blocked>: <action>`. Maestro is required only where it is used (`input: adb` or flows). |
| S11 | Skills and docs | No procedure commits by itself; `/qa-report` writes only its report; bug approval is one batch review; references to removed skills are gone; `where` and `sync_skills` say when the installed skills include uncommitted changes. Sync never deletes or writes through a link, and retires only what its own record installed. |

written with the fixes and pass now, but only some were run against the old code (the run log, report and pbi_state
ones, whose old tests had to change).
